## 产品与固定范围

用户是装修、建材类学员，希望借短视频建立个人IP、获客。小程序只提供对标视频SOP和文字AI辅助。

- 品牌为“聚梦传媒”，人物称谓统一“IP”。
- 底部固定两个导航，原样保留“对标 SOP”“聚梦AI”，默认进入SOP。
- 不增加首页、我的、课程、作业、打卡、商城、排行榜、智能体广场或额外Tab。
- SOP目录固定五类：量房、开工、成品案例、见客户、巡检。复用已有9案例54镜数据。
- 首版文字聊天与SOP上下文；不扩展图片/视频识别、会员付费或新的业务系统。

## 视觉方向：之前 Lei 的风格

参考仓库brand/中的“聚梦”头像：米白、黑色宋体、橙红小圆点，大留白，克制的编辑排版。

- 建议基调：米白#F7F5F0、近黑#161616、灰色辅助文字、橙红#CC603D作为少量强调色。
- 中文标题使用系统可用的宋体或衬线字体栈，正文使用清晰的系统无衬线字体；不依赖外网字体才能正常显示。
- 清楚的字号层级、充足间距、轻分隔线和少量必要容器，避免满屏卡片堆叠。
- 不做紫蓝渐变、霓虹、玻璃拟态、过度阴影、3D装饰、夸大营销标语。图标统一简洁线性风格，不用emoji拼界面。
- 头像只是风格依据，不要求所有地方重复Logo；原有Lei预览若出现多余导航或智能体模块，仅参考视觉语言，不沿用其产品结构。

## 需要设计并落地的界面

1. SOP目录：五类选择和该类案例列表，重点让学员快速找到现场类型、知道案例要拍什么。提供清晰的进入/继续阅读动作。
2. 案例照拍：完整原片入口、当前参考片段、第几镜/共几镜、上一镜/下一镜/重播，以及六项信息——站在哪里、手机对准哪里、开始后做什么、IP说什么或问什么、什么时候停止、拍够的标准。主动作是“带入聚梦AI，按现场调整拍法”。信息多时可用分组和层级组织，不能藏掉关键指令。
3. 聚梦AI：直接可用的聊天页。顶部或页面内部放新建和历史入口，显示当前SOP上下文，输入框上方只放少量示例。正文清晰，支持复制、停止、失败重试；键盘弹出时输入区和发送按钮可操作。
4. 必需状态：加载、空对话、模拟模式、媒体未配置/加载失败、生成中/已停止/失败、断网、未开通、额度不足。仅呈现已有业务支持的状态，不伪造后台能力。

## 实现约束

- 使用微信原生WXML、WXSS、TypeScript。不要提交只能在浏览器运行的HTML/React/Tailwind网页来代替小程序。
- 遵循UI_HANDOFF中的路由、字段、事件和接口。优先改变WXSS和布局；必要时拆原生组件，保留原事件语义。
- 保留video object-fit=contain，不裁掉关键画面；保留切镜、切Tab、离开页面暂停和续看机制，不自动连播。
- 明确显示模拟状态，不把模拟回复包装成真实AI。AI生成内容与用户文字有清晰区分。
- 保留用户历史隔离、额度和服务端密钥边界。不要为设计预览改动权限、使用假交易案例或写死个人历史。
- 兼顾小屏手机、长中文、系统字体回退、安全区域和键盘；点击区充足，辅助文字仍可读。
- 若补充展示字段，先检查数据能否提供，并同步类型、绑定、数据示例与UI_HANDOFF，不凭空引用不存在的字段。
