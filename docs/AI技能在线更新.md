# 在小程序里更新 AI Skill

更新：2026-11-02。入口：任意Tab顶部Logo菜单 → 老师后台 → 输入管理密码 → AI Skill。

本轮先把技能从代码中的固定指令改为服务端可维护内容。首次需要同步升级服务端和小程序；此后日常修改文字规则不需要重新构建、重启服务或重新提交小程序版本。生产部署与微信发布本轮尚未执行。

## 日常使用

1. 选择已有Skill，或点击新增Skill。
2. 填写名称、给客户看的说明、自动识别词、提问引导、执行规则和显示顺序。
3. 正文可直接粘贴，也可从微信聊天文件选择Markdown/TXT导入。单文件最多128KB，正文最多16000字。原文件不上传到服务端，只提交确认保存的文字。
4. 先保存草稿，检查后发布给客户。草稿不会影响客户当前使用的规则。
5. 客户重新打开聚梦AI后同步最新技能列表。发布后的新提问使用新版，已开始的任务保留原版；历史回答保留当时的名称与版本。

自动识别词用逗号分隔，最多24个、每个1–40字；留空的技能仍可由客户手动选择。自动选择仍按问题中的文字匹配，未识别的补充沿用上次技能；识别不准时手动选择。新增技能进入处理方式菜单，排序靠前的前4项成为空态常用入口。

## 以后按流程服务客户

可以把下面这些内容写进执行规则：适用场景、开始前必须知道的事实、信息不足时怎么问、按什么步骤分析、何时等待客户选择、输出格式、结束前检查什么。

这些规则会连同当前对话和可选SOP交给模型。阶段和追问目前由模型依据正文与对话执行，系统尚未提供强制阶段状态机、多Agent调度或工具执行。导入的正文如果引用其他文件，应把必要内容合并进正文；不会自动读取本地Skill目录、scripts或references。联网、视频识别、文件生成等能力仍需另行接入。

## 版本与停用

发布内容变化时生成新版本；网络重试发布同一份内容不会重复增加版本。可恢复上一发布版到草稿，检查后再发布。恢复草稿本身不会改变客户正在使用的版本。

停用后客户列表不再展示该Skill，新任务不能使用它、不扣次；已有任务和历史记录保留。默认现场拍摄可以编辑，但保留为通用处理入口，不能停用。多人编辑发生冲突时会提示刷新，避免覆盖别人刚保存的修改。

## 保存位置与接口

线上维护内容保存在DB_PATH指定的SQLite里，默认server/data/jumeng.sqlite。新增ai_skills、ai_skill_versions表，任务JSON保留私有规则快照；旧会话与计次表兼容。GitHub只同步代码与初始默认技能，老师后来维护的内容不会自动写入GitHub。换服务器或备份时需保留同一数据库；升级不会重新覆盖老师已经编辑的默认技能。

老师沿用现有登录、管理密码、会话绑定及过期规则。`GET/POST /teacher/skills`用于管理草稿；`POST /teacher/skills/:id/publish|unpublish|restore`提交revision控制修改冲突。电脑管理接口/api/skills同样支持这些操作。

客户`GET /skills`只返回已发布技能的名称、说明、引导、排序和版本，不返回执行正文或草稿。发送接口的skill字段支持服务端发布的动态ID；同一requestId恢复原任务、原版本和原计次。会员期限、每日上限及一次新发送扣1次的规则不变。
