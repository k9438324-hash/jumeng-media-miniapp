# 换电脑、换 AI 怎么继续

## 第一次在另一台电脑打开

需要 Git、Node.js 24.16 或更新的 24.x，以及微信开发者工具。先下载代码：

```text
git clone https://github.com/k9438324-hash/jumeng-media-miniapp.git
cd jumeng-media-miniapp
npm ci
npm run setup
npm test
npm run dev
```

然后在微信开发者工具导入工程根目录，不是 miniprogram 子目录。保留运行服务的终端。首次是本机模拟模式，不会自动获得真实微信身份或调用付费模型。

以后同步前先保存本机改动，再在 main 分支执行 `git pull --ff-only origin main`；不要用强制覆盖命令丢弃本机工作。

## 让另一个 AI 接手

可以直接把下面这段话和仓库地址发给它：

> 请继续维护这个聚梦传媒小程序。先读 AGENTS.md、NEXT_AI_HANDOFF.md，再按任务读 UI_HANDOFF.md 或 docs/老师后台.md。保留米白底、黑色文字、橙红点缀、三项底部导航和顶部 Logo 菜单。老师后台入口在 Logo 菜单内，密码只由服务器校验。视频加 SRT 拆解使用 skills/jumeng-video-sop/SKILL.md。先查看实际代码和 Git 状态，不把历史验证当作当前已上线。

技能已随仓库提供；AI 可以直接读取其 SKILL.md 执行。希望在其他项目也能调用时，另运行：

```text
npx -y skills add k9438324-hash/jumeng-media-miniapp -g --all
```

安装后新开 AI 对话或刷新技能列表，使用 `$jumeng-video-sop`。本技能的素材准备、媒体处理需要 Python 3、FFmpeg 和 FFprobe；这些只在做视频拆解时使用，小程序普通构建不依赖它们。

## 哪些东西不会跟 Git 同步

Git 同步源码、界面、技能和默认课程数据。以下内容需要另行配置或私密迁移：

- `server/.env`：API Key、微信 AppSecret、后台密码摘要和机器配置。新机器运行 setup 只创建空白示例，不会复制真实凭证。
- 数据库及上传目录：后台新增的 SOP、草稿、发布状态、学员、会员次数、历史记录和上传视频保存在服务端数据目录，不进入 Git。
- 原视频、SRT 和技能任务输出：仍在用户本地任务目录或媒体库，不进入 Git。
- 微信开发者工具登录、开发权限、合法域名和服务器配置：需在新机器单独准备。

如果只是换电脑开发，可以继续连接同一个已部署服务。如果要把本机运营数据也搬过去，先停止小程序服务和老师网页后台，再通过可信的私密渠道备份并复制完整数据库目录及 uploads，核对 DB_PATH 和外部 MEDIA_ROOT。不要把运行中的 SQLite 主文件单独复制，不要将学员数据或密码提交到仓库。

## 当前验证范围

新技能已用构造的视频和 SRT 做链路测试：生成三镜课程、导入独立数据库草稿、重复导入不重复新增、老师发布、学员目录读取、完整片及分镜访问，以及开发者工具内实际播放和切镜。测试没有修改原有课程或学员权益，也没有部署微信线上版本。

用户真实视频的拆解质量、新人照拍效果、真机及线上媒体仍需用真实材料验证。
