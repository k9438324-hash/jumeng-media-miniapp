# 视频拆解成照拍 SOP

## 输入与交付

输入是用户指定的视频和对应 SRT，目标是让第一次拍视频的人按步骤完成拍摄。沿用聚梦小程序五个分类和课程格式，不重建项目。

交付四样东西：

1. `sop.md`：先讲整条视频为什么这样拍，再逐步教怎么拍和检查。
2. `delivery.json`：课程、分镜、来源证据及未确认信息。
3. `media/` 和 `package.json`：用户需要上传时生成的 MP4、分镜片段和封面，以及媒体路径已补齐的课程文件。
4. 导入结果：默认是后台草稿；只有用户明确要求发布，才使学员可见。

开始读取 [格式与写法](references/sop-format.md)。读取项目 `AGENTS.md` 和当前课程及后台实现，优先使用现有代码。

## 工作流程

### 1. 核对材料

确认视频和字幕实际存在并一一对应；只有其中一项时，说明缺少哪项。仅字幕时可交付“文字草案”，不得声称看过画面、完成视频拆解或进入发布步骤。仅视频时询问对应 SRT，不自动购买转录服务。

在项目忽略提交的 `output/` 下，为本次任务创建一个新目录；不覆盖旧任务。运行：

```text
python <skill>/scripts/prepare_materials.py --video <视频> --srt <字幕> --out <新任务目录/materials>
```

脚本验证时长和字幕时间，输出逐条字幕、抽帧清单与图片。读取 `materials/manifest.json`；逐张查看输出图片，依据需要补看原片或在关键时间附近补帧。抽帧不足以看清动作连续性时，写明限制，不假称完整看过视频。字幕偏移必须由对照证据确认，再用 `--offset` 调整；不猜偏移。

### 2. 先说明观众要明白什么

用一句话写清观众看完应明白的事。识别镜头如何依次提供证据，例如“先看到问题 → 再看到一次真实操作 → 最后核对效果”。这是对本条视频的解释，不能宣布所有视频都必须套这个顺序。

分镜按动作、画面、话题及作用变化划分，不按每句字幕机械拆分，不强凑六步。以原片真实时间为依据。

### 3. 每镜变成能照着做的动作

每镜写明：让人明白什么、为什么拍、站哪里、手机拍什么、谁做什么、怎么说、何时结束、怎么检查。

- 一步一个主要动作；把抽象词换成能看见的对象和动作。
- 需要术语时当场解释，例如“近景，就是让手和正在做的东西占满大部分画面”。
- 先给能直接模仿的做法，再解释理由；不要只改标题而保留难懂正文。
- 时间和“原片实际做法”来自画面/字幕证据；距离、机位或台词改编属于照拍建议，单独标注。
- 不知道原片站位时，写“原片未展示站位；照拍建议：……”，不杜撰原片摄影师的位置。
- 原话和建议说法分开；字幕出现的效果承诺不自动当成已证明事实。
- 学员正文只保留拍摄目标、准备、动作和检查。分类代码、文件结构、导入状态及测试过程放在老师核对记录，不塞进 `need`、`takeaway` 或操作正文。

### 4. 写课程并自查

按参考格式写 `delivery.json`。`lesson.id` 固定为 0，代表新增；每镜列出对应字幕编号、看过的帧及观察事实。证据不足时填写 `unverified`，仍可保存草稿，禁止自动发布。

```text
python <skill>/scripts/check_delivery.py <任务目录/delivery.json> --manifest <任务目录/materials/manifest.json> --render <任务目录/sop.md>
```

逐镜检查：“一个新人拿到这条说明，能知道下一步手和手机该怎么动吗？怎么知道拍够了？”不能用格式校验代替可读性判断。把没有看懂的原因和补拍建议告诉用户。

### 5. 生成媒体包并导入草稿

用户要求上传到小程序时，先生成可播放素材：

```text
python <skill>/scripts/package_media.py <任务目录/delivery.json> --manifest <任务目录/materials/manifest.json> --out <新任务目录/ready>
node <skill>/scripts/import_draft.mjs --project <工程根目录> --input <任务目录/ready/package.json> --media <任务目录/ready/media>
```

第二条默认只检查，不写数据库。检查通过后，在已获“上传/导入”授权的范围内加 `--write` 导入新草稿。使用服务运行时相同的 `DB_PATH`；在工程目录运行，按项目现有方式加载本机环境文件，不打印其内容。导入脚本不修改打包课程，不覆盖已有案例；重复导入同一包不会新增第二份。

用户明确要求发布时，才加 `--publish`；存在未确认信息时拒绝发布。用户只说“拆解”时交付文件即可，不自动写入数据库。

### 6. 验证实际结果

草稿应在老师后台可见、在学员 `/course` 中不可见。明确发布后，检查学员课程、分镜文字、封面、视频与 Range 播放响应；有开发者工具时实际打开新课程播放。缺少真机或线上环境时分别说明，不能把本机通过描述成微信上线。

测试走独立数据库和端口，不为演示修改真实学员额度。发布到 GitHub 需要用户单独授权；只上传 Skill、必要代码和脱敏说明，不上传视频、字幕、抽帧、任务输出、账号、口令或数据库。

## 停止与边界

- 对应关系或关键时间无法确认：交出待确认位置，暂停发布。
- 视频无法读取或图片查看工具不可用：标记视觉验证未完成，不靠字幕编画面。
- 不把安装、施工等操作的原片演示自动扩展为专业操作指导；本技能交付拍摄方法。
- 不调用付费 API，不把本机路径作为公开运行依赖，不擅自覆盖课程、购买媒体托管或部署。

脚本成功只证明材料和数据链路通过；“小学生也能懂”仍需用读者反馈验证。最终说明本轮看过的材料范围、交付位置、草稿/发布状态及尚未完成的验证。
