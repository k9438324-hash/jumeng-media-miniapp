# 课程格式与写法

分类只能从现有五项选择：`measure` 量房、`start` 开工、`case` 成品案例、`meet` 见客户、`inspect` 巡检。按内容选，不按视频文件名猜；不能区分时问用户归哪类。

## delivery.json

顶层是 `schemaVersion: 1`、`category`、`lesson`、`evidence`。不要输出整个课程库。

`lesson` 字段：

| 字段 | 内容 |
| --- | --- |
| id | 必须为 0，新增草稿 |
| name | 简短案例名，说清这次做什么 |
| task | 看完这条视频让人明白什么 |
| need | 什么时候适合拍、要准备什么 |
| takeaway | 各段画面如何让观众一步步看懂 |
| file | 初稿为空；媒体打包后是 videos/ 下的 MP4 相对键 |
| duration | ffprobe 得到的实际秒数 |
| shots | 1—100 镜；按内容需要拆，不固定为六镜 |

每个镜头：

| 字段 | 新人读到后应知道 |
| --- | --- |
| title | 这一镜想让人明白什么 |
| logic | 为什么需要这张画面，它解决什么疑问 |
| where | 出镜的人和拿手机的人分别站哪儿 |
| frame | 手机横竖、镜头朝向、必须拍进来的东西 |
| action | 谁先做什么，然后做什么；尽量只保留一个主要动作 |
| say | 可直接说的话；原话和改编建议要分清 |
| stop | 出现什么画面或动作后，可以停止拍摄 |
| check | 拍完立即检查哪一件能看见、听见的事 |
| ref / end | 原视频真实起止秒数，0 ≤ ref < end ≤ duration |
| keep | 对照片段长度，等于 end - ref |
| clip / clipPoster / image | 初稿可为空；已有素材只允许 clips/ 或 assets/ 下的相对键 |

每镜的 `evidence` 项与 `shots` 顺序对应：

- `shot`：从 1 开始的镜头编号。
- `cues`：实际支持该段内容的 SRT 序号数组。
- `frames`：已查看的 manifest 帧文件名数组，覆盖本段而非随便选一张。
- `observed`：这些帧里实际看见的对象与动作，不写摄影师未展示的站位。
- `adaptation`：为方便学员模仿提出的机位、台词、时长等建议；没有可为空。
- `unverified`：尚未确认的事实数组，没有则是空数组。有值只允许草稿。

字幕只能证明“说了什么”；静帧不能单独证明完整动作完成、机器效果或因果关系。拿不准就写进 `unverified`，不要为了通过校验编造证据。

## 大白话自查

- 不只写“交代场景”，改为“先把房门和房间一起拍进去，让人知道你站在哪间房”。
- 不只写“突出卖点”，改为“按一下开关，把开关和亮起来的灯放在同一张画面里”。
- 不只写“自然结束”，改为“等出镜的人说完最后一句，再多拍一秒”。具体秒数属于照拍建议，不是假称原片一定这么做。
- 不要求学员拥有原片同样的房子和器材；写明需要保留的关系，以及可以替换的物品。
- 每段的检查方法必须可观察，例如“回放时能同时看到手按开关和灯亮”，不能只写“效果好、有质感”。

## 草稿与发布

先运行 `check_delivery.py`，媒体打包后再检查 `package.json`。导入脚本默认只校验；`--write` 新增草稿，`--write --publish` 才发布。重复导入同一个包复用原记录，不覆盖教师后续在后台做的修改；如需替换既有课程，请在老师后台校对处理。

原始文件只读；生成的 MP4 是另存副本。视频、SRT、抽帧、JSON 输出和试跑记录放在工程忽略提交的任务目录，不能跟随技能公开。
